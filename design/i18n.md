# Languages (draft-3)

Two separate problems, both first-class:

1. **UI languages** — the app's own chrome, switchable inside the app. The owner is building towards 13 languages; the app must be able to follow.
2. **Multilingual content** — tasks, projects, lines and notes are written in many languages and scripts at once (Russian, English, Italian, German, Latvian today; Chinese, Japanese, Greek, Hebrew, Arabic later). The app shows them correctly, searches them well and never translates them.

---

## 1. UI languages

### Waves

| Wave | Languages                                                                               | When                                          | Translation quality                                                         |
| ---- | --------------------------------------------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------- |
| 1    | English (base), Russian                                                                 | Phase 1 (S4)                                  | Owner-reviewed                                                              |
| 2    | Latvian, Italian, German                                                                | A translation slice after phase 1 (no code)   | Latvian owner-reviewed; IT/DE AI-translated, owner-reviewed as level allows |
| 3    | French, Spanish, Portuguese (BR), Greek, Chinese (Simplified), Japanese, Hebrew, Arabic | On demand (owner's polyglot plan or audience) | AI-translated + native review before "shipped"                              |

**Architecture supports wave 3 from day one** (RTL, CJK, complex plurals) even though only wave 1 ships in phase 1: retrofitting RTL or plural rules later costs far more than respecting them now.

### Switching

- **Settings → General → Language**: `System` (default) + every _shipped_ language, each shown in its own name (`English`, `Русский`, `Latviešu`, `Italiano`, `Deutsch`, …).
- Applies to the app only. Mechanism per ADR-0009: stored choice + relaunch, unless the S4 spike proves a reliable live switch. macOS per-app language (System Settings → Language & Region → Applications) keeps working.

### Rules for every screen

1. **No string literals in views.** All UI text from the String Catalog (`Localizable.xcstrings`). Core returns values (`quietDays: 29`, `kind: .session`), never display text.
2. **Plurals from CLDR via the catalog**, never `if count == 1` in code. The catalog must cover every category each shipped language uses: EN one/other · RU one/few/many/other · LV zero/one/other · AR zero/one/two/few/many/other · HE one/two/other · ZH/JA other.
3. **Dates, numbers, durations** through `FormatStyle` in the chosen locale (decimal comma, month names, 24-hour time). Exceptions (product rules, same in every language): **ISO weeks** (Monday first, ISO week numbers) and the Gregorian calendar for all data.
4. **RTL:** with Hebrew or Arabic UI the whole layout mirrors (SwiftUI default — don't hard-code `.leading`/`.trailing` as left/right, don't use fixed x offsets). Directional SF Symbols use their `.forwardslash`-aware variants; charts keep time flowing in reading direction. Acceptance runs with Xcode's "Right-to-Left Pseudolanguage".
5. **Length:** translations run up to +40 % (DE, RU, EL) and much shorter (ZH, JA). No fixed-width label may clip; columns truncate at the tail with a tooltip. Acceptance uses Xcode's "Double-Length Pseudolanguage" at 1100×700.
6. **Tone rules in every language** — `tone-glossary.md` holds the canonical terms and banned words per shipped language; CI greps the catalog per language.
7. **Fallback:** a missing translation falls back to English, never to a key; a language is "shipped" only at 100 % coverage + tone check.

## 2. Multilingual content

### Rendering

- Every displayed title carries a **content language** (see Detection). Text views set it (`AttributedString` `languageIdentifier`), so the system picks correct glyph variants (Japanese vs Chinese Han forms), hyphenation and line breaking.
- **Bidi isolation:** a Hebrew or Arabic task title inside an English or Russian UI renders right-to-left without disturbing the row; mixed chips (`Project → 🎻 Line → Artifact`) isolate each segment (Unicode first-strong isolates), so arrows and order stay correct in both directions.
- Truncation is by grapheme cluster (Swift `String` default; never by bytes or UTF-16 units) — emoji flags, combining accents and CJK stay intact.
- Fonts: SF system font with system fallback for every script. No bundled fonts.

### Detection

- A `LanguageDetector` **port** in Core (Core stays platform-free); the macOS adapter uses `NaturalLanguage` (`NLLanguageRecognizer`), tests use a fixture detector.
- Short titles are unreliable, so detection uses **hints**: the line's declared language (`language: it` on a language line), the owner's language list (Settings → Content languages), then the recogniser constrained to that list. Result + confidence stored in `attrs` JSON; below a threshold → "unknown", rendered with the UI language.
- Detection runs at import, off the main thread, cached by text hash.

### Search (⌘K, S5)

- SQLite **FTS5 with the `trigram` tokenizer**, case-insensitive, diacritics removed — works for any script including Chinese and Japanese (no word segmentation needed) and matches substrings.
- Queries shorter than 3 characters (below the trigram length) use a case- and diacritic-insensitive **substring** scan, so `提琴` finds `练习小提琴`.
- Ranking stays as specified (exact word > prefix > substring; today's tasks first).
- Later option: transliteration-aware search (`skripka` finds `скрипка`) via ICU transforms on the query only.

### Sorting

- User data keeps **source order** (vault / OmniFocus order) wherever it exists. Where the app must sort text, it compares with an **explicit locale** — the selected UI `Locale` (the in-app language, not the system one): `lhs.compare(rhs, options: [.caseInsensitive, .numeric], range: nil, locale: uiLocale)`. Not `localizedStandardCompare`, which always uses the current system locale.

### The assistant (phase 4)

- Accepts questions in any language and answers in the language of the question; data is passed untranslated; evals include cross-language cases (a Russian question about Italian tasks).

## 3. Polyglot features (future, recorded so the model allows them)

- **Language lines know their language**: optional `language: it` on a line in the budget note. Enables per-language weekly exposure (sessions, tasks, later minutes from the hours tracker) next to the polyglot plan's hour targets.
- **Immersion mode**: UI in a target language, hold ⌥ to reveal the same label in the owner's primary language. A natural fit for wave 2 (IT, DE).

## Files

- `Apps/Mac/Resources/Localizable.xcstrings` — the catalog of the app's UI text.
- `Apps/Mac/Resources/InfoPlist.xcstrings` — the Info.plist strings, such as the Automation prompt's `NSAppleEventsUsageDescription` (S4-4c-1).
- `design/copy.md` — canonical EN/RU strings; `design/tone-glossary.md` — tone terms and banned words per language.
