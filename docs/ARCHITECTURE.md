| `Artifact` / `Goal` | title, horizon, target period, parent, line, status                                                                                                                                                                           | Obsidian notes (year artifacts, quarter focus)                                                                                                                                                                            |
| `Project`           | title, line, artifact?, milestones, status; anchors: OmniFocus project 0..1, project note 0..1, notes of the project, mentions (ADR-0014)                                                                                     | OmniFocus projects (mapped by tag/folder) and vault project notes (`moonshine: project`; ADR-0014)                                                                                                                        |

| `Plan`              | project, steps (DAG), template?                                                                                                                                                                                               | MoonShine native                                                                                                                                                                                                          |

| `Capture`           | text as dictated, device, time, state (`new/interpreted/closed`)                                                                                                                                                              | native, saved before any network call (ADR-0013)                                                                                                                                                                          |
| `Proposal`          | source capture, summary, commands with previews, impact, alternatives, state                                                                                                                                                  | native, made by the assistant (ADR-0013)                                                                                                                                                                                  |
| `TimerSession`      | subject, startedAt, state (`running/paused/stopped`), device, target?                                                                                                                                                         | native, synced; up to three running at once (ADR-0016, amended 2026-10-16); produces one `TimeEntry` per interval (ADR-0016)                                                                                              |
| `Reminder`          | text (1–500 characters), line or project?, display (`pinned/scheduled`), schedule (once; daily, weekdays or chosen weekdays at a time; every N hours, N 1–12, inside a window), notify, quiet window?, archived, omnifocusId? | native, synced (ADR-0010); created by the owner or converted from a bridged OmniFocus task; seen, never done; in phase 1 OmniFocus tasks with the reminder tag are shown read-only instead (ADR-0017)                     |
| `ReminderSeen`      | reminder, occurrence, device, seenAt                                                                                                                                                                                          | native, synced; seen on one device is seen everywhere after sync (ADR-0017)                                                                                                                                               |
| `Link`              | source note, target as written, resolved note?, kind (`wikilink/embed/markdown/frontmatter/moonshine`), line; no alias, anchor or other body text                                                                             | the link index, built from note bodies on the Mac; provider-sourced, synced read-only (ADR-0014)                                                                                                                          |
| `Ritual`            | name, moment (`morning/evening/weekly/manual`), line or project?, template path, target, section heading                                                                                                                      | native, synced; the template stays an ordinary Obsidian template (ADR-0015)                                                                                                                                               |
| `Command`           | typed change, target ids, parameters, autonomy class (`auto/confirm`), origin, state, undo data                                                                                                                               | native; executed by the `CommandBus` (ADR-0013)                                                                                                                                                                           |

**Identity:** every entity has a MoonShine `UUIDv7` id plus zero or more `ExternalRef`s. Swapping OmniFocus for another provider re-links refs; ids and history (time entries, forecasts) survive.

## Key flows

- **Sync-in (phase 1):** providers produce snapshots → `Store` upserts by `ExternalRef` → Services read only from `Store`. Completed tasks outlive the import window; other missing items are soft-deleted (ADR-0002), except lines, which are soft-deleted only after a clean vault read (2026-10-07), and notes and artifacts, which are soft-deleted only when the read saw that they are gone: one the read could not see or no longer recognises stays as stored (2026-10-10). Imports are single-flight per service, and a commit names the store version its identity map was read at (stale → `IdentityConflict`). UI is fast and works offline; providers refresh on launch / ⌘R / timer.
- **Commands (phase 2 for native data; the Write phase for the vault; the Act phase for OmniFocus and calendars):** UI or assistant emits `Command` (e.g. `LogTime`, `AddTakeNote`; later `CompleteTask(id)`) → `CommandBus` → every command lands in the activity log with undo. Phase 2 introduces the bus for MoonShine-native writes (time entries, takes, capacity exceptions); the Reminders slice adds the reminder commands (ADR-0017). In the Act phase the bus checks provider **capabilities** → adapter executes → Store refreshed; a provider command created on another device is queued and executed by the Mac (ADR-0013).
- **Vault commands (the Write phase):** UI or assistant emits a vault command (`CreateNote`, `AppendToNote`, `UpdateNoteBody`, `SetNoteProperty`) → `CommandBus` → `VaultWriter` in the `ObsidianAdapter`: role folder check, precondition (hash of the content it was based on; mismatch → nothing written, both versions shown), atomic replace, byte fidelity, previous content kept 30 days for undo. Only the Mac writes; a vault command from the iPad or iPhone is queued under the once-only rules of ADR-0013. A ritual renders an Obsidian template into a draft; nothing is written before the owner saves (ADR-0015).
- **Timer (phase 2, Timer slice):** `StartTimer` (switches: stops the running session at that instant and offers `Keep both` for about eight seconds; ⌥-start runs alongside; up to three at once, a fourth start stops the oldest) → `TimerSession` → each interval between start, pause, resume and stop becomes a `TimeEntry` (source `timer`; split at local midnight) → edits through `EditTimeEntry` / `SplitTimeEntry` with undo → the import reconciles native and `excel` entries by (day, line): within 10 minutes the pair resolves as "the same session" and can be reopened from the day view, beyond it the pair goes to the reconcile list; the owner's choice is stored, and no entry is ever negative (ADR-0016). Lines' hours count their own entries in full; the day's clock time is the union of intervals and never exceeds 24 h.
- **Reminder notifications (the Reminders slice):** `NotificationPlanner` in Core reads reminders, `ReminderSeen` and running timers and decides what to schedule for the next 24 hours → the per-device `Notifier` adapter schedules local notifications (at most 64 pending; a running timer's nudges rank first, then reminders by time; what does not fit waits for the next refill) → refills on launch, on wake, on background refresh and whenever a reminder changes. A reminder seen or archived on one device removes its pending notifications on the others when the change arrives (ADR-0017). In phase 1 (S4) only the tag bridge exists: OmniFocus tasks with the reminder tag are shown in Today's Reminders strip and excluded from every task count; notifications stay with OmniFocus.
- **Take (phase 2):** the owner's judgement of a line's week. Rhythm, progress and take are three tracks, never summed; a take does not change forecasts.
- **Forecast (phase 2–3):** evidence → Calibration (bias, adherence per line) → ForecastEngine simulates the scenario over Capacity → bands per step/project → Planner view models; weekly job stores ForecastSnapshots.
- **Assistant (phase 4):** conversation → `AIProvider` with tool schemas from `ToolRegistry` → read tools execute immediately (note bodies only from the folders on the assistant's allowlist, ADR-0015); write tools return a _proposal_ (a `Command` preview) the user confirms. From phase 4 a voice `Capture` becomes `auto` commands (applied at once) or a `Proposal` the owner confirms. Until the Act phase `auto` covers native commands (log time, add a take note, start, pause, resume and stop a timer, edit the entry just stopped, ADR-0016; create, edit, mark seen, snooze, archive and convert a reminder, ADR-0017) and one provider command, `AppendJournal` (ADR-0015); from the Act phase it also covers `CompleteTask` and `CreateTask` (inbox), executed through the queue. Provider changes in a proposal are shown as a checklist with deep links until the Act phase; a failed or unresolved `auto` command lands in the review inbox (ADR-0013).

## Module / folder layout

```
MoonShineCore/        SwiftPM: Domain, Services, Assistant, Ports, Fixtures
Adapters/             SwiftPM targets per adapter (OmniFocus, Obsidian, Claude, Excel, SQLite)
Apps/Mac/             SwiftUI app (XcodeGen project.yml)
Apps/MCP/             swift executable exposing ToolRegistry as MCP server
bridge/               Omni Automation JS for the OmniFocus adapter
fixtures/             synthetic data only
docs/                 VISION, ROADMAP, ARCHITECTURE, adr/, specs/, method/
```
