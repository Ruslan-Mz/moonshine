## Views

### Today

- Available tasks with planned/defer = today, flagged, and real `due` ≤ today (only **deadlines** among these may use the urgent colour — see Deadline rule below).
- **Anchors strip** (decision 2026-10-01, design draft-2) at the top: today's tasks with the tag `anchor` (leaf name), up to 5 compact chips (first 5 in source order); the count covers **all** of today's anchors (`3 of 6 done`); done anchors stay visible, checked and dimmed. Absent when there are none. Only anchors shown in the strip are left out of their line sections; further anchor tasks stay there. An anchor is a task with a tag of its **own** whose leaf name is `anchor`, both trimmed and case ignored, the leaf match the deadline tag uses (`Tag.matchesLeafName`); a tag on the task's project or action group does not count (owner, 2026-10-26). A done anchor shown in the strip stays only there; Done today lists every other task completed today, anchors beyond the first five included, and the `done` count covers them all (owner, 2026-10-26).
- **Top 3 today**: open flagged tasks (`effectiveFlagged`), at most 3 rows — a real due date today or earlier first, then source order (owner, 2026-10-26); when more are flagged, a `5 flagged — 3 shown` caption and "Show all" (the choice kept per window; from the keyboard, ⌥⌘F in the View menu, owner 2026-10-26). These tasks are not repeated in their line sections. A flagged task shown in the Anchors strip is not a Top 3 candidate, and the caption counts the candidates only. Top 3 is the table's first section, under the column header (owner, 2026-10-24). The snapshot contract already carries `flagged` / `effectiveFlagged` and `tagIds` (no S3a change).
- **Done today** (owner, 2026-10-24): every task completed today but the done anchors shown in the strip, in one section at the end of the list, after Life ops, most recent first by completion time (the same time keeps source order); the 3 most recent are visible, the rest behind an `N more` disclosure (kept per window, opened from the keyboard like Life ops). A done task is in no line section, Top 3 or From earlier, and never urgent; it counts in the subtitle's `done` and in Touched today, unless its line is paused: a paused line's tasks count in `done` only (owner, 2026-10-27). The subtitle's `open` and estimate cover every open task of Today, Top 3, the strip, From earlier and Life ops included.
- Grouped by line (emoji + name), **foundation lines first**, then vault order; each task shows project and trace chip (`project → line → artifact`).
- **From earlier:** available tasks planned on an earlier day, in their own section with the planned age ("planned 3 days ago"); urgent only with a real `due` (decision 2026-09-30). Its header shows the count, `From earlier (8)`, and it collapses and expands like Life ops, expanded by default, the state kept per window (owner, 2026-10-26).
- Right rail: **Quarter focus card** on top (the current quarter note's `artifacts:` with a neutral done/not-done glyph and line emoji, `2 of 5 done`, link "Open quarter note" (S4-5); absent without a quarter note, and when the current quarter note has no artifacts; dropped artifacts are left out of the rows and the count (owner, 2026-10-28). The current quarter note is the first `quarter_focus` note by path whose period is of scale quarter and holds now: chosen by type as the trace chooses year notes, and by the period's scale because the reader keeps a `quarter_focus` note with any period, a year's with its list, and the card's quarter comes from that period (PR #36 round 1)), then lines touched today, "quiet lines" (active, no completion ≥ 14 days), neutral wording. An active line with no completions at all is "no activity yet", not quiet. **Rail rules (S4-1b-2):** a quiet or no-activity line's next step is its first available next action in source order, the "Next actions" rule of Lines (owner, 2026-10-24); a line with none reads `no next action`. Foundation lines are never quiet; a foundation line with no completions at all is "no activity yet", with its first step (owner, 2026-10-28). Touched today shows each line's sessions and tasks of the day, never summed; a session counts on a day when any of its completions falls on it, weeks keep its first completion (owner, 2026-10-27). Life ops has its own row in Touched today, `🧺 Life ops` (owner, 2026-10-27). Paused lines are not in Touched today; their tasks still count in Done today (owner, 2026-10-27). A line whose completions are all older than the import window (`window.completedSince`) reads "no activity yet" until S4-4c carries the window start into the workspace, so the rail can say "no completions since <date>" (owner, 2026-10-27). With nothing to show, the rail holds one line, `Nothing on the rail today` (owner, 2026-10-27). The rail is an inspector, shown by default at every window size, 1100×700 included, and hidden with ⌃⌘I (`InspectorCommands`) or the toolbar button (owner, 2026-10-27). Its strings are in `design/copy.md` (owner, 2026-10-27).

- **Day rail** (design draft-3, `design/screens/today.md` § Calendar): today's events and the tasks with a planned or due time on the day window; free time = what remains of the day window from now. Checkboxes on the rail are read-only, as in the list.

### Week

- 7 columns (Mon–Sun, ISO week); each task appears once, on its planned date, else defer date, else due date; a deadline (deadline rule below) due inside the same week adds a due badge on the item; "No plan" tray for available tasks in active lines without any date (mirrors the owner's "Без плана" perspective).
- Header: per line completions this week vs. last 4-week average (numbers, not red/green).
- Calendar events in each day column, all-day bars, per-day time in calendar; the weekly review gains "Fixed next week" (`design/screens/week.md` § Calendar).
- The weekly review layout leaves room for the third track (`My take`, `design/screens/week.md` § My take); no code for takes in phase 1.

### Lines

- The Lines layout leaves room for a third track under the sparkline (`My take`, `design/screens/lines.md` § My take); no code for takes in phase 1.
- One row per line from the vault, grouped by **tier** (decision 2026-10-01, design draft-2 — replaces grouping by `block`): Foundation → Active this season → Maintenance → Paused on purpose (titled "Not in focus — on purpose", collapsed by default); vault order inside a tier. The `block` is a small label under the line name. Foundation lines are never "quiet". Columns: budget h/week (from vault; foundation lines show `floor N h/day` instead), 8-week completions sparkline (current week marked partial), last activity, available next actions, planned effort (estimate, labelled as estimate).
- Line detail: parent artifact (open in Obsidian via `obsidian://open`), projects, next actions, last 10 completions.

### Global

- Sidebar: Today, Week, Month, Lines. ⌘1–⌘4. ⌘K command palette (navigate, search tasks/projects/lines/notes). ⌘R refresh.
- Every task/project opens in OmniFocus via `omnifocus:///task/<id>`; every note in Obsidian.
- Status bar: source (Demo / Live), "updated N min ago".
- Settings: vault folder (security-scoped bookmark), source Demo | Live, refresh timer (ADR-0011), Calendars (ADR-0012), deadline rule.
- **Deadline rule** (owner decision 2026-10-02): a setting with two modes, "all due dates" (default) and "due date + tag" (tag name configurable, default `deadline`, matched by leaf name like `anchor`, trimmed, case-insensitive, empty reverts to `deadline`; the tag counts on the task or on any of its ancestors — action group or project — so an inherited due date follows the same rule). Amber (due badge, due mark, urgency on Today and Week) applies only to deadlines under the active rule; any other due date is plain secondary text. Exception (owner, 2026-10-27; ADR-0020, CLAUDE.md rule 8): a strong quota's time state and its period that ended short are amber too; no red anywhere. The rule is a Core value used by Overview. Reason, counts only: 61 live repeating tasks carry a due date used as a reminder.
- Demo mode runs with a frozen clock at 2026-10-01 16:20 (Thursday, ISO week 40, the dataset's time zone: `Europe/Moscow`, owner 2026-10-20), so it renders like `design/demo-data.md` and the mockups, and the same on any Mac; the views format dates in that zone. Live mode uses the system clock.
